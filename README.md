Практична робота №2 з дисципліни "Програмування мовою Java". Варіант: Ващенко Владислав Олександрович.

- Тип: `Duration`
- Дані: `list/Duration.data`
- List: `Vector`
- Set: `TreeSet`
- Queue: `PriorityQueue`
- Точне значення для пошуку: `PT0H1M36S`
- Умова вибірки даних: Пошук тривалостей, більших за 2 хвилини (PT2M)
- Параметри вибірки даних: threshold = PT2M

## Як запустити

Скомпілювати й виконати з кореня репозиторію (GitHub Codespaces, JDK 21):

```bash
javac *.java
java BasicDataOperations "PT0H1M36S" "PT2M"
```

У Windows PowerShell перед запуском:

```powershell
chcp 65001
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

Перший аргумент це точне значення для пошуку, другий це нижня межа вибірки.
Верхньої межі в цьому варіанті немає, умова одностороння. Необов'язковий третій
аргумент це шлях до файлу даних. Формат ISO-8601, як у файлі `list/Duration.data`.

Очікуваний результат: у консолі послідовно виводяться блоки операцій з масивом,
List, Set і Queue, і для кожної операції тривалість у наносекундах.

## Що змінено відносно прикладу

Тип `LocalDateTime` замінено на `Duration` у всіх шести файлах. Разом із типом
прибрано `DateTimeFormatter`: `Duration.parse()` читає ISO-8601 без форматера.

`Duration` не має методів `isBefore()` і `isAfter()`, тому всі порівняння
переведено на `compareTo()`.

Умова вибірки змінена з інтервалу на одну межу, тому програма приймає два
аргументи замість трьох. У відсортованих даних бінарний пошук знаходить перший
елемент, більший за межу, а далі весь хвіст підходить без додаткових порівнянь.

`ArrayList` замінено на `Vector`, `HashSet` на `TreeSet`. `PriorityQueue`
лишився без змін, бо він і був у варіанті. Коментарі про внутрішню будову
`HashSet` переписано під `TreeSet`: це червоно-чорне дерево, пошук у ньому
O(log n), а не O(1).

## Результати запуску

Завантажено значень: 200, з них унікальних 160, повторів 40.
Найменше значення PT1M1S, найбільше PT3M40S.
Умові "більше за PT2M" відповідає 125 значень.

До сортування вибірка переглядає всі 200 елементів, після сортування 132:
бінарний пошук за кілька кроків доходить до межі, а далі йде готовий хвіст.
